# v0.1 release validation

This checklist records validation evidence for the Windows desktop build. It is
not release approval. Run it again against the portable executable and NSIS
installer after packaging issue [#107](https://github.com/DarrenPratt/Drelwick/issues/107)
is complete. See [desktop packaging](desktop-packaging.md) for commands and the
current packaging evidence below. Do not describe a source-built Electron launch
or an unpacked-app smoke check as an installer test.

Apply the [proposed branding and official distribution policy](branding-distribution-policy.md)
when preparing release descriptions: packaged, signed and official are distinct.
Ordinary CI/PR artifacts are not official releases. Record owner authorisation,
approved channel, edition/version/source revision and actual integrity/signing
evidence for any designated release. #107 owns packaging implementation; #59's
legal/artwork review and #60's public-release gate remain pending. The policy
draft and validation evidence do not themselves authorise publication.

## v0.1 gate status

- [x] The planned v0.1 implementation issues #2–#50 are closed on GitHub.
- [x] The available Windows runtime scenarios above pass.
- [x] macOS/Linux and standalone-packaging limitations are recorded.
- [x] The known periodic-history runtime integration gap is resolved and verified by the history lifecycle tests and Windows E2E run.
- [ ] Final v0.1 release signoff: no known data-loss defects remain after owner review of all recorded validation evidence.

The initial validation found that closed issue #36's core snapshot service was
not connected to desktop editing and that retention had no normal runtime
caller. The desktop main process now schedules snapshots from successfully
saved chapters, retains the latest saved content for five-minute interval
snapshots while saves continue, applies retention after project open, and
settles history work on project close and clean shutdown. Tests verify these
runtime paths and ensure history failures do not block saves or log manuscript
content. This resolves the identified history integration gap; it does not by
itself assert that no other data-loss defects exist or replace owner release
review.
