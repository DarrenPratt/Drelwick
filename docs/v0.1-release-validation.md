# v0.1 release validation

This checklist records validation evidence for the Windows desktop build. It is
not release approval. Run it again against the portable executable and NSIS
installer after packaging issue [#107](https://github.com/DarrenPratt/BookEditor/issues/107)
is complete. Do not describe a source-built Electron launch as an installer test.

## Environment and result

Validated on 21 September 2026 with the repository at `575fa7e`, Windows 11 Pro
(10.0.26200), Node.js 24.20.0, pnpm 10.34.5 and the repository-pinned Electron
39.1.2. The application was built from source and launched as an isolated
Electron app. This validates the current Windows runtime path, not a fresh
standalone installation.

| Check                                          | Result   | Evidence                                                                                                                                                                                              |
| ---------------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Frozen dependency install                      | Pass     | `pnpm install --frozen-lockfile` completed without lockfile changes.                                                                                                                                  |
| Fresh standalone install                       | Deferred | No portable executable or installer exists yet; verify both Windows artifacts after #107.                                                                                                             |
| Create a project and ten chapters              | Pass     | `pnpm test:e2e`, `tests/e2e/desktop.spec.ts`; isolated project created through the UI.                                                                                                                |
| Reorder chapters                               | Pass     | The test moves Chapter 10 above Chapter 9 and checks persisted manifest order.                                                                                                                        |
| Write formatted prose and insert a scene break | Pass     | The test checks bold text and the semantic scene-break node in project files and after reopening.                                                                                                     |
| Verify autosave                                | Pass     | The test waits for **All changes saved** without invoking Save, then checks the on-disk document.                                                                                                     |
| Restart and verify content                     | Pass     | The test exits normally, relaunches with the same isolated user-data directory, and opens the saved project.                                                                                          |
| Simulate forced shutdown and recover           | Pass     | The test terminates the Electron process tree, relaunches against an unclean session marker, recovers the synthetic history candidate, and verifies recovered content plus the pre-recovery snapshot. |
| Verify renderer Node access is disabled        | Pass     | The runtime test confirms `process` and `require` are absent from the renderer window; `window-options.ts` sets `nodeIntegration: false`, `contextIsolation: true` and `sandbox: true`.               |
| macOS/Linux runtime and packaging              | Not run  | No macOS/Linux host was available. Packaging targets and artifacts remain pending #107.                                                                                                               |

The forced-shutdown scenario uses the canonical synthetic `recovery-project`
fixture. It does not copy real manuscript content. Test directories and user
settings are isolated and removed after each run.

## v0.1 gate status

- [x] The planned v0.1 implementation issues #2–#50 are closed on GitHub.
- [x] The available Windows runtime scenarios above pass.
- [x] macOS/Linux and standalone-packaging limitations are recorded.
- [ ] Release signoff: no known data-loss defects remain.

Release signoff remains open. The core history snapshot and retention functions
exist, but repository search found no desktop runtime call to
`createHistorySnapshot` or `applyHistoryRetention`. `createHistorySnapshot` is
called by recovery only for the mandatory pre-recovery snapshot; retention has
no runtime caller. The design and chapter-persistence documentation describe
periodic snapshots during editing, but they are not wired into the application.
Resolve and test that integration before asserting the no-data-loss gate. This
checklist does not silently treat closed issue #36 as proof of runtime behavior.

After #107 supplies standalone artifacts, extend this record with fresh-install,
launch and asset-loading results for the Windows portable executable and NSIS
installer. Add macOS DMG and Linux AppImage/deb results when those platforms are
available; otherwise keep their limitations explicit. No unsigned release is
published as part of this validation.
