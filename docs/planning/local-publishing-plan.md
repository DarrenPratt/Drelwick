# Local publishing delivery plan

Decision date: 19 September 2026. Planning issue: [#109](https://github.com/DarrenPratt/Drelwick/issues/109).

This plan turns the Atticus gap analysis into local desktop delivery work. It supplements the original v0.1 plan without reopening its scope. Issues are requirements, not evidence of implemented features. Main at the planning baseline was `37a7bb8`: manuscript editing, chapter management, autosave, retained history and crash recovery existed; import and publishing did not.

## Product decisions

- Basic local DOCX import (v0.2) and editable manuscript DOCX export (by v0.3) are CORE. Preserve supported content, surface conversion warnings and never promise exact Word page-layout fidelity.
- Complete v0.1 reliability validation before releasing the next workflow. Bring basic manuscript search/replace, chapter convenience operations, history restore and offline spelling forward to v0.2. Story-bible search and richer revision tools remain later.
- Authoritative project files, all conversion/rendering, preview and EPUB/basic PDF export remain local and work without an account, network connection or Pro checkout.
- Cloud editing, collaboration and live multi-device project synchronization are outside the current roadmap. Optional off-device backup to user-owned Google Drive, Wasabi or Git repository storage is research, not a provider selection or integration commitment.
- Use immutable consistent archives for optional storage-provider backup. For Git repositories, compare archive commits with commits of validated staged project snapshots. Explicit restore creates a new local project; provider failures never block editing. Explore encryption/key recovery, credentials, retention and verification before implementing an adapter.
- The backup exploration is CORE architecture research with no release milestone. Future client adapters require a separate scope/classification decision; third-party storage fees do not automatically make the application feature SERVICE.
- Advanced themes, reusable pages, parts/volumes and richer semantics first receive design issues. Their completion requires focused implementation follow-ups; the design milestone does not claim implemented parity.

Git repository research includes private hosted or self-hosted remotes, scoped SSH/HTTPS credentials, binary assets/LFS, repository growth, rejected pushes, history retention and explicit commit-based restore. A local commit alone is not an off-device backup. Do not automatically merge into the active manuscript, force-push or rewrite remote history. Evaluate hooks, filters and untrusted repository configuration as part of the adapter boundary. Broader interactive Git/version-control tooling remains a separate future feature.

## Implementation guidance

Issue #129 implements local Chromium pagination and a PDF-backed full-book/facing
preview, consuming #128 settings and #121 semantic assembly/rendering. See
[the pipeline, typography limits and acceptance evidence](../print-preview.md).
Final destination export/preflight remains #130; release/platform validation is #131.

Treat document conversion as a potentially lossy transformation with explicit warnings and testable content preservation. Import into staged new projects; never modify the source DOCX. Persist schema changes through recoverable migrations. Flush pending edits before snapshots, bulk replacements, backup and export, or fail explicitly without claiming success.

Use synthetic and redistributable fixtures for Unicode, long books, complex formatting and malformed archives. Gate output on independent EPUB/PDF/DOCX inspection and appropriate reader/platform checks. Do not log author prose, search strings or document payloads.

HTML/Markdown export, full tracked changes and story-bible features remain broader design intent outside this publishing slice. Large image spreads, advanced publisher profiles and premium themes require the advanced-publishing design decision. Do not infer that every Atticus feature must be copied.
