# Add explicit hardcover interior recommendations over Community print settings

<!-- DRELWICK-133-AP3 -->

Tracking: [#237](https://github.com/DarrenPratt/Drelwick/issues/237); design owner #133.

## Objective and scope

Implement an optional local, profile-driven interior assistant over existing trim,
mirrored margins/gutter and edition settings. Manual ordinary novel printing,
including a manually configured hardcover interior, remains Community functionality.

## Classification and readiness

**Undecided — owner review after #203** (`product:undecided`). No existing CORE
settings or exports move to Pro. Backlog until #133/AP1 (#235) are merged, actual print
foundations verified and technical scope approved. #203 evaluates approved private
scope/deferrals before final allocation; it is related, not a reverse dependency.

## Acceptance criteria

- Require a pinned profile with exact binding/stock/page-count inputs and provenance.
  Unknown/expired/incomplete instructions produce explicit uncertainty, not guesses.
- Explain suggested trim/margins/gutter and constraints in user units; do not select
  a universal gutter/spine formula or claim manufacturer compliance.
- Applying is explicit: preview before/after and save via ordinary expected-revision
  validation/atomic print persistence. Never modify prose or silently change the
  other print edition, EPUB, running matter or author's manual settings.
- Re-pagination and a fresh production proof are required after geometry changes;
  detect nonconvergent/changed page-count assumptions and invalidate stale advice.
- Existing Community settings and basic preflight work when no profile/assistant
  is installed or a profile is unavailable.
- Clearly separate interior from case wrap, boards/hinges, jackets, endpapers,
  covers/spines and printer-provided components. Existing cover metadata is not
  a manufacturing template. No such output is generated by this issue.
- Accessible keyboard/dirty/cancel/reopen workflows preserve previous valid state.

## Expected components

AP1 (#235) model/profile/measurement APIs; core recommendation planning over existing print
settings; shared bounded DTOs; desktop assistant and current print-settings/preview
integration; synthetic fixtures and provider-source review documentation.

## Security and persistence

Profiles remain passive and offline. No script/rule plugins, fetched instructions,
credentials, arbitrary paths or automatic settings fixes. Reuse shared lock,
context transactions, atomic writer, backup and stale checks. Maintain restricted
IPC and Electron controls; do not log manuscript/private profile fields. No Pro.

## Automated acceptance tests

T01/T05/T06/T09/T10/T11/T12: unit conversions, gutter added once, multiple synthetic
bindings/stocks, missing/expired/unknown inputs, source/profile/page-count changes,
explicit apply/cancel, invalid geometry, failed writes/restart and independent
edition/EPUB/prose bytes. Verify Community publishing without profiles or network.

## Manual acceptance tests

Keyboard review/apply/reject with two source-verified printer profiles and a physical
proof. Confirm exact stock/binding/page-count assumptions, inspect actual page
geometry and explain unsupported cases. Record platform/printing limitations;
do not use local tests as a printer acceptance or cover/spine guarantee.

## Dependencies and exclusions

Dependencies: merged #133/AP1 (#235); implemented #128/#129/#130/#136. No CT1 (#232)–CT3 (#234) or AP2 (#236)
dependency for ordinary interior advice. Exclude cover/case wrap/spine/endpaper
generation, ISBN/upload APIs, physical ordering, automatic provider updates,
licensing decisions, arbitrary rule execution, cloud and Pro. Related to #133/#203.
